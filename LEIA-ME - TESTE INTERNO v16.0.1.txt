O ZIP COMPLETO é uma cópia de teste separada da v16.0 Cloud Ready. Ele inclui data/db.json NOVO de demonstração, 1.148 cadastros de clientes únicos e 1.386 itens importados da planilha. A planilha de clientes tinha uma entrada repetida; o sistema evita duplicação por documento. O ZIP DE ATUALIZAÇÃO inclui código, scripts, biblioteca de importação e os dados da planilha para migrar o banco EXISTENTE; deliberadamente NÃO contém data/db.json, backups, chaves nem senhas em texto puro. NÃO use o ZIP COMPLETO para atualizar a AWS, pois o banco do ZIP não contém os registros comerciais reais do seu servidor.

2. ATUALIZAÇÃO ONLINE - AWS LIGHTSAIL (SOMENTE DEPOIS DE APROVAR O TESTE LOCAL)
IMPORTANTE: o servidor conhecido do histórico atende em https://c4usystem.ddns.net, mas NÃO tivemos acesso SSH nem conferimos qual código/banco está realmente rodando agora. Estes passos exigem um operador autorizado, acesso SSH e janela de manutenção. Uma atualização altera usuários e dados reais; não execute se não tiver backup/restauração validados.
A. No Windows, mantenha o ZIP original oficial guardado. Baixe o ZIP DE ATUALIZAÇÃO, não o ZIP COMPLETO. Abra PowerShell em uma pasta com o ZIP e envie usando sua chave SSH, ajustando caminhos:
  scp -i "C:\CAMINHO\SUA-CHAVE.pem" "C:\CAMINHO\C4U_APP_v16.0.1_ATUALIZACAO_TESTE.zip" admin@c4usystem.ddns.net:/home/admin/c4u-update.zip
B. Conecte-se: ssh -i "C:\CAMINHO\SUA-CHAVE.pem" admin@c4usystem.ddns.net
C. Descubra a instalação real antes de continuar: pm2 status; cd "/home/admin/c4u/C4U APP"; pwd; ls -lah; ls -lah data/db.json; confirme que o servidor e o banco correspondem à instalação correta. Se C4U_DATA_DIR estiver configurado, confirme seu caminho. Se os caminhos forem diferentes, adapte TODOS os comandos de migração.
D. Agende manutenção e interrompa gravações: pm2 stop c4u. Crie cópia COMPLETA fora da pasta ativa, sem sobrescrever cópias anteriores:
  mkdir -p /home/admin/c4u-rollback
  cp -a "/home/admin/c4u/C4U APP" "/home/admin/c4u-rollback/app-$(date +%Y%m%d-%H%M%S)"
  cp -a "/home/admin/c4u/C4U APP/data/db.json" "/home/admin/c4u-rollback/db-$(date +%Y%m%d-%H%M%S).json"
Se o banco estiver fora desta pasta, copie o banco real. Salve os uploads reais, configuração PM2/Nginx e backup externo/offsite protegido. TESTE que os backups podem ser lidos antes de continuar.
E. Inspecione antes de extrair: unzip -l /home/admin/c4u-update.zip. O ZIP foi criado com server.js e public/ na raiz; NÃO contém data/db.json. Extraia para a pasta correta somente após conferir o destino:
  unzip -o /home/admin/c4u-update.zip -d "/home/admin/c4u/C4U APP"
F. Entre na pasta, valide JavaScript e dependências:
  cd "/home/admin/c4u/C4U APP"
  node --check server.js
  node --check public/app.js
  npm install --omit=dev --no-audit --no-fund
G. Execute a migração SOMENTE sobre a base real: node scripts/apply-update.js. Se usar C4U_DATA_DIR, configure-o explicitamente também neste comando e no provisionamento. O script produz backup adicional, importa os 1.148 clientes e os 1.386 itens sem apagar cadastros, e repetições por código/documento não duplicam esses registros.
H. Provisione exclusivamente os sete usuários: node scripts/provision-users.js. Digite as senhas quando solicitadas pelo terminal; elas não serão ecoadas. O script preserva IDs correspondentes e histórico, desativa contas fora da lista e registra novo backup. Giovana entra com login "giovana". Não digite senhas em argumentos de linha de comando, scripts ou registros compartilhados.
I. Inicie e verifique: pm2 restart c4u --update-env (se não reiniciar um processo parado, use pm2 start c4u); pm2 status; pm2 logs c4u --lines 50; sudo nginx -t. Confirme login com sete perfis, Clientes, Biblioteca, cotações, links HTTPS, dados históricos, SSE/Chat e permissões. Ao concluir: pm2 save.
J. Se algo falhar: pare c4u, preserve uma cópia de registros novos gerados desde o backup, restaure os arquivos do aplicativo da pasta de rollback e o banco apenas após avaliar mudanças posteriores; reinicie pm2 c4u e revalide. Evite sobrepor manualmente pastas de versões diferentes. Se o deploy atual divergiu da v16.0, interrompa e faça comparação de código primeiro.
